# Apple Core 1.0.5

Apple Core 1.0.5 makes `/favicon.ico` serve a real icon file, so clients that read connector branding from the origin can actually decode it.

## Fixes

- **`/favicon.ico` returns a real ICO container**: the route answered with a bare 32x32 PNG body labelled `image/png`. The path claims an ICO container and the content type disagreed with both the path and the bytes, which strict icon resolvers reject outright. The rendered PNG is now wrapped in a genuine single-entry ICO and served as `image/x-icon`. Every other favicon size is unchanged.
- **The landing page advertises fewer, smaller icons**: it listed all seven PNG sizes, which put a 256x256 image ahead of anything cheap. Icon resolvers take the first usable declaration, so the page now offers the ICO plus the 16 and 32 pixel PNGs. All sizes remain served for clients that request them directly.

## Notes

These routes stay unauthenticated and unconditional, so pointing your own Cloudflare Tunnel at Apple Core vends the Apple Core logo from your own domain with no extra configuration.

If your MCP client still shows a different icon after updating, the cause is likely outside Apple Core: some clients resolve a connector's icon at the registrable domain rather than the exact hostname, so a subdomain's own favicon may never be requested.

## Upgrading

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the [1.0.3 notes](https://github.com/oliverames/apple-core/releases/tag/v1.0.3), because their update signing key no longer matches the feed.
