# Apple Core 1.0.7

## Fixed

- Enabling a service from the status menu no longer fails with "Apple Core could not become the active app". Activation is now re-requested while waiting and treated as best-effort, so the permission request itself always runs.
- When macOS refuses to display a permission dialog (the request comes back denied but no decision is recorded), Calendar, Contacts, Reminders, and Capture now report that the prompt was suppressed instead of claiming access was denied. The message points at non-default security configurations — for example `amfi_get_out_of_my_way` in `boot-args`, which marks every third-party process as a platform binary and causes macOS 26 (Tahoe) to deny consent prompts outright.

## Notes

- If a Mac's toggles fail with the new "macOS refused to display the permission request" message, no in-app change can help: restore the default security configuration (clear the custom `boot-args`, re-enable SIP) or grant access by other means, then try again.
