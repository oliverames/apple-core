# Apple Core 1.5.0

Three corrections to the Filesystem surface, found by auditing it against the running server. One of them changes how `filesystem_write` behaves, so it is worth reading before updating.

## Writing no longer replaces a file by accident

`filesystem_move` and `filesystem_copy` have always refused to overwrite, for a stated reason: a replaced file does not go to the Trash, so it is the one destructive act on this surface with no undo. `filesystem_write` was the exception. It replaced whatever was at the path and reported the fact afterwards, and it is the tool a client reaches for when it believes a file is new.

**`filesystem_write` now refuses to replace an existing file unless you pass `overwrite: true`.** The error says so and names the alternatives, so a client that meant to update a file can retry deliberately, or use `filesystem_append` instead.

This is a behaviour change. Anything that relied on write silently replacing a file needs `overwrite: true` from now on. Creating a new file is unaffected.

## Searching contents no longer claims to be truncated when it isn't

`filesystem_search_content` re-checks every Spotlight hit against the shared folders, because `mdfind` is a separate process and must not be the access control. It then measured truncation against the raw hit count, so any hit dropped for sitting outside a shared folder made a complete answer report `truncated: true`. Callers were told to narrow a search that had already returned everything they were allowed to see.

Truncation is now measured against the matches you can actually be shown.

## Hidden files behave the same in both tools

`filesystem_list` showed dotfiles and `filesystem_search` skipped them, so a file you could see when listing a folder could never be found by name. Both now include hidden files, and both take `includeHidden` if you would rather leave them out. Hidden is decided by the filesystem's own flag, so a file hidden without a leading dot is treated correctly too.

## Upgrading

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the [1.0.3 notes](https://github.com/oliverames/apple-core/releases/tag/v1.0.3), because their update signing key does not match the feed.

No new permissions, and shared folders are unchanged. The only thing to check is whether anything you have automated calls `filesystem_write` expecting it to replace a file.
