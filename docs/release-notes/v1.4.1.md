# Apple Core 1.4.1

A fix for a connection that could hang, introduced by 1.4.0, plus two smaller corrections to the new Cloudflare Access settings.

## A coalesced connection could park forever

1.4.0 gave the shared token a stable approval identity, which is what made approving it once work. It also meant that connections arriving while an approval dialog is already open are recognised as the same subject and wait on that one answer rather than opening a dialog each. That part is intended and is why one approval now settles several waiting clients at once.

What was missing is the case where the connection holding the dialog goes away before anyone answers, because the client gave up or the transport died. The waiting connections were left with nothing to resolve them and would hang until the process restarted. They are now denied along with the connection that dropped.

This was unreachable before 1.4.0, since every shared-token connection had its own identity and so nothing was ever coalesced onto it.

## Cloudflare Access settings

- Turning the protection off no longer asks for an API token when there was never anything to remove. Enabling the toggle, changing your mind, and having no token left you unable to turn it back off.
- The list of allowed people is filled in from what is already saved when Settings opens. It previously showed an empty field even when addresses were configured, so applying again looked like it would clear them.

## Upgrading

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the [1.0.3 notes](https://github.com/oliverames/apple-core/releases/tag/v1.0.3), because their update signing key does not match the feed.

Nothing to redo. Clients you have already approved stay approved.
