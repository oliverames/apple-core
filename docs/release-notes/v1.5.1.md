# Apple Core 1.5.1

Clarity, mostly. Sharing a folder now tells you what you have actually shared, and asking macOS for permission to control Mail, Messages or Notes works from inside the app instead of sending you somewhere that cannot help.

## Shared folders say what they expose

Every shared folder used to look the same in Settings: a name, a path and a switch. Sharing one project directory and sharing your entire home folder read-write were presented identically, and adding a folder that already sat inside another shared folder said nothing at all.

Folders now carry a plain-language note when there is something worth knowing:

- **Your whole Home folder.** Called out as covering everything in it, including app data and saved passwords, with the suggestion that Documents is usually enough. Marked more strongly when writing is allowed.
- **The whole disk**, if a folder above your home folder is shared.
- **Already covered.** A folder inside another shared folder is marked as adding nothing, so it can be removed.

An ordinary folder says nothing. Advice nobody needs is noise, and noise is what gets ignored when it matters.

## Permission to control Mail, Messages and Notes

Two separate problems in Diagnostics, both of which made a working setup look broken or an unfinished one look impossible.

**"Mail not running" was misleading.** macOS cannot report an automation grant while the target app is closed, and the panel showed that failure as though it were the answer. It now says it cannot check while the app is closed, which is what is actually true. Permission may well already be granted.

**"Open Settings" was a dead end.** System Settings only lists apps that have already asked for automation, so a service that had never requested it had no row there to switch on. Nothing you could click would help.

There is now a **Request Access** button on those rows. It asks macOS directly, showing the usual consent prompt, which is also what makes the app appear under Automation in System Settings afterwards. The target app is opened quietly in the background first, because the request cannot be answered for an app that is not running, and it is not brought to the front. Settings is still offered for a permission you have actually refused, since macOS will not ask again about those.

Opening Diagnostics still never prompts on its own. Consent is only ever requested when you press the button.

## Two ways to connect, described as two things

Settings said "Every client uses the same address and token", which is not true and blurred two different mechanisms.

- **Apps on this Mac** connect with the address and your token. It is one long-lived secret, the same for every one of them, and it identifies no particular client.
- **Apps on the web** sign in through a page instead and get their own credentials, which can be withdrawn one at a time. They never need the token pasted anywhere.

Each group now says which of the two it uses, and the shared token and OAuth clients are described in their own terms rather than as one idea.

**Copy Address and Copy Token are separate buttons.** They were one button that copied both on two lines, which then had to be pulled apart again, since clients ask for the address in one field and the token in another.

## Smaller

The Shared Token row in Settings › Clients now leads with what it describes rather than with its status, matching the rows beneath it.

## Upgrading

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the [1.0.3 notes](https://github.com/oliverames/apple-core/releases/tag/v1.0.3), because their update signing key does not match the feed.

Nothing to redo, and no new permissions. Existing shared folders and approvals are untouched; the folder notes are descriptions of what you already have.
