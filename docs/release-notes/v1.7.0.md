# Apple Core 1.7.0

Three changes, two of them found by watching a real connection fail.

## A tunnel belongs to one Mac

A Cloudflare tunnel is one identity, and its credentials travel with the config file. A second Mac that launched Apple Core with a copy of that config became a second connector on the same tunnel, and Cloudflare spread requests across both. Every request that landed on the Mac without Apple Core failed, and from a cloud client that looked like "authorization failed" with the right token.

Apple Core now records which Mac set the tunnel up. A copy of the config on another Mac stands down at launch instead of adding a connector, and says so in the Access pane with a choice: take the tunnel over on this Mac, or turn it off here. While the tunnel runs, the pane also asks Cloudflare how many Macs are connected and reports more than one as an error rather than a green check.

Configs from earlier releases have no owner recorded. The Mac that launches with such a config enabled becomes the owner, so nothing changes for an existing single-Mac setup.

## Trust granted from the authorization page

A new client's first connection used to wait for a dialog on the server's screen. On a Mac nobody is sitting at, that dialog was never answered and the client saw nothing but a timeout.

The person filling in the OAuth authorization page has already typed the Apple Core token, which is the same authority the dialog asks for. The page now trusts that client on the Mac in the same step. The box is on by default, says where the dialog would otherwise appear, and says when that screen has nobody at it. Trust granted this way appears in Settings alongside trust granted from the dialog and can be withdrawn there.

## License activation

The signed app now needs a license file before it serves MCP. Until one is activated in **Settings → License**, session-creating requests answer **402 Payment Required**, and `/license-status` says so without authentication. Builds from source are not affected. See `docs/licensing.md` in the repository for how licenses are issued.

## Upgrading

Updates now download from `assets.amesvt.com` rather than a GitHub release asset. GitHub releases carry source and notes only.

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the [1.0.3 notes](https://github.com/oliverames/apple-core/releases/tag/v1.0.3), because their update signing key does not match the feed.

No new permissions.
