# Apple Core 1.0.3

Apple Core 1.0.3 repairs automatic updates and rebuilds Cloudflare Tunnel setup around a guided flow.

## Update this release manually

The update signing key has changed. Builds from 1.0.0 through 1.0.2 carry a public key whose private half is no longer available, so they cannot validate the update feed and show "The update feed is improperly signed and could not be validated." Download 1.0.3 from [Releases](https://github.com/oliverames/apple-core/releases/latest) and replace the app once. Automatic updates work normally from 1.0.3 onward.

Earlier notes claimed this was fixed in 1.0.1. That was wrong: the feed was well-formed, but it was signed with a different key than the one shipped in the app, so no release could ever verify it.

## Fixes

- **Hostnames with a scheme or path are accepted**: pasting `https://mcp.example.com/mcp` into the Cloudflare Hostname field now reduces to `mcp.example.com`. Previously the whole string went to `cloudflared tunnel route dns`, which rejected it as an invalid hostname, and the failure appeared only in the log.
- **Routing failures are visible**: a DNS route that cannot be created is reported in the Cloudflare pane instead of being discarded. A tunnel that starts without routing anywhere is no longer reported as a success.
- **Tunnel status tells the truth**: the pane no longer shows "Cloudflare tunnel started" beside a Stopped badge. Loading the LaunchAgent is now confirmed to have produced a running process before the app claims it started.

## Cloudflare setup

- **A Before You Start checklist** shows whether `cloudflared` is installed and whether you are signed in to Cloudflare, with the exact command or button to fix each.
- **Log In to Cloudflare** runs the browser sign-in from inside the app. Apple Core detects the resulting account certificate rather than failing later with an opaque error.
- **Set Up & Start** replaces Start Tunnel as the primary action, and runs the whole sequence: find or create the named tunnel, route the hostname in DNS, write the config and LaunchAgent, then start. Start Tunnel skipped DNS routing and now lives in Tunnel Actions as "Start Tunnel Only".
- **Every field explains itself**, and the Hostname field shows inline why a value cannot be routed.
