# Apple Core 1.1.1

Apple Core 1.1.1 tightens client identity, OAuth revocation, remote setup, and the bundled command-line bridge. It also makes failed settings saves visible before Apple Core changes the tunnel or installs anything.

## Client security

- Connection approval now separates the authenticated OAuth registration from the MCP name a client reports for itself. Apple Core saves permanent trust by OAuth client ID, while clients using the shared bearer token still require approval for each connection.
- The Clients pane lists every registered OAuth client. Disconnecting one revokes its authorization codes and tokens, closes its active sessions, and removes its saved approval.
- OAuth clients can revoke access and refresh tokens through the advertised revocation endpoint. Revoking a refresh token also revokes access tokens from that authorization grant, and a failed disk write cannot report a successful revocation.
- OAuth resource values must match the advertised MCP address exactly, so a token cannot be issued for a URL variant that the server will not accept.

## Connections

- The bundled `apple-core` command now uses the MCP SDK's streaming HTTP transport. Server notifications reach standard output while other requests are running, and cancellation keeps JSON-RPC string and numeric identifiers distinct.
- Cancelling a request closes its matching HTTP response stream instead of leaving the client waiting on a response that will never arrive.
- HTTP sessions stay bound to the authenticated client that created them. A different client cannot reuse a valid session identifier.

## Remote access

- Cloudflare setup verifies that the public hostname is an exact CNAME for the selected tunnel. An existing record that points somewhere else now stops setup with an actionable error instead of being accepted.
- Apple Core verifies a downloaded `cloudflared` binary before installing it. Atomic replacement keeps the verified binary executable and preserves the installed copy if replacement fails.
- Settings now reports a configuration write failure and keeps the existing file unchanged. Tunnel setup, shutdown, and `cloudflared` installation stop before they can create external state that Apple Core cannot save.

## Updates

- Sparkle release notes now use stable GitHub links for older versions, and each release includes a SHA-256 checksum beside the notarized app archive.

## Upgrading

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the [1.0.3 notes](https://github.com/oliverames/apple-core/releases/tag/v1.0.3), because their update signing key does not match the feed.
