# Apple Core 1.4.0

Apple Core 1.4.0 is about being asked to approve things. Connecting with the shared token used to mean answering a dialog on every single connection, with no way to stop it. Now one approval is enough. Alongside that, Cloudflare Access can be put in front of the one page where the token gets typed.

## Approving a client once

Connecting with the shared Apple Core token prompted for approval every time, and ticking a box to remember the answer was never offered. That was not a small oversight: the approval subject was a fresh identifier per connection, so nothing could ever match what had been approved before. Reconnect, restart the client, restart the Mac, and you were asked again.

- The approval dialog now offers to remember the shared token, and remembering it works. Approve once and clients using that token connect without asking again.
- The grant is tied to the token itself, so **rotating the token revokes it**. A new token starts from an unapproved state, which is what you would want if you rotated it because the old one leaked.
- The dialog says what it is actually asking. Trusting the shared token trusts anything that presents it, rather than one particular client, and the wording no longer implies otherwise.
- Settings › Clients has a Shared Token section showing whether that grant is in place, with a control to require approval again. Trust you cannot see is trust you cannot withdraw.

OAuth clients are unchanged and keep their existing approvals. Nothing needs to be re-approved after updating.

## A login in front of the authorization page

The OAuth authorization page is where the Apple Core token gets typed into a browser, and it is the only page on the server a person visits. Cloudflare Access can now be placed in front of it, from Settings › Access, so reaching that page requires a Cloudflare login first.

It protects that page and nothing else, deliberately. The MCP endpoint and the client registration and token endpoints are called by client software with no browser and no one to satisfy a login, so putting Access over the whole host would stop every client connecting. Apple Core will not do that: the protection is scoped to the single path, and the code refuses to create a rule covering the machine endpoints even if asked.

Setting it up needs a Cloudflare API token with Access permissions. The credential from `cloudflared` sign-in is not enough, because it is scoped to tunnel and DNS work. The API token is kept in the Keychain rather than in the config file, since it can change Zero Trust policy for the whole account.

This is off by default and changes nothing until you turn it on.

## Upgrading

1.0.3 and later update automatically. Installs on 1.0.0 through 1.0.2 still need the one-time manual reinstall described in the [1.0.3 notes](https://github.com/oliverames/apple-core/releases/tag/v1.0.3), because their update signing key does not match the feed.

No new permissions. If you have already approved clients, they stay approved.
